## 大纲生成 / Outline Generation

### 1. 技术博客大纲

```
为以下技术主题生成一篇技术博客的完整大纲。

主题：[TOPIC]
目标读者：[TARGET_AUDIENCE]（如初级/中级/高级开发者）
文章长度：[WORD_COUNT] 字左右
语气风格：[TONE]（如专业严谨/轻松幽默/教程风格）

大纲要求：
1. 标题（3 个备选，含主关键词）
2. Meta Description（155 字以内）
3. 引言（含钩子和读者痛点）
4. 4-6 个主要章节，每章含 2-3 个子要点
5. 代码示例标注（标注需要代码的位置）
6. 总结和 CTA
7. 内链/外链建议位置
```

### 2. Listicle 类型大纲

```
生成一篇 "[NUMBER] 个 [TOPIC]" 类型的 Listicle 博客大纲。

主题：[TOPIC]
数字：[NUMBER]
目标关键词：[KEYWORD]

每个列表项需要：
- 标题（吸引眼球）
- 一句话概述
- 详细说明要点
- 配图建议
- 实际案例或数据

额外要求：
- 排序逻辑合理（按重要性/难度/时间线）
- 每项之间有过渡语
- 在列表中间加入"意外"项以保持阅读兴趣
```

### 3. How-to 教程大纲

```
为以下操作指南类主题生成教程大纲。

主题：[TOPIC]
读者技术水平：[SKILL_LEVEL]
预计阅读时间：[READ_TIME] 分钟

大纲结构：
1. 前置条件和准备材料
2. 概述（完成后能获得什么）
3. 分步指南（每步含：操作、截图位置标注、预期结果）
4. 常见问题和排错
5. 进阶技巧
6. 总结
```

### 4. 对比分析文章大纲

```
为以下对比主题生成深度对比文章大纲。

对比对象：[ITEM_A] vs [ITEM_B]
使用场景：[USE_CASE]
目标关键词：[KEYWORD]

大纲要求：
1. 引言（为什么这个对比重要）
2. 候选者概览（各自简介）
3. 多维度对比（性能/价格/易用性/生态等）
4. 对比表格
5. 使用场景推荐（什么情况下选 A，什么情况下选 B）
6. 结论和个人推荐
```

## 开篇钩子 / Intro Hooks

### 5. 数据驱动钩子

```
为以下话题写一个用数据/统计开篇的博客引言。

话题：[TOPIC]
相关数据：[DATA_POINTS]（如"90% 的开发者在第一次部署时犯过这个错"）
文章主旨：[MAIN_POINT]

引言要求：
- 第一句用震撼数据吸引注意
- 解释数据的意义和读者的关联
- 过渡到文章要解决的问题
- 总长 100-150 字
- 让读者感到"这篇非读不可"
```

### 6. 故事型钩子

```
用一个引人入胜的故事开头来引入以下话题。

话题：[TOPIC]
故事方向：[STORY_DIRECTION]（如个人经历/行业案例/假设场景）
核心观点：[KEY_POINT]

引言要求：
- 用第一人称或第三人称叙事
- 故事与话题自然衔接
- 包含冲突或意外
- 引出文章要解决的问题
- 总长 150-200 字
```

### 7. 问题型钩子

```
用一个读者无法忽视的问题开篇。

话题：[TOPIC]
读者痛点：[PAIN_POINT]
解决方案预告：[SOLUTION_PREVIEW]

引言结构：
1. 直击痛点的问题（让读者点头）
2. 扩大问题的影响范围
3. 简述问题的严重后果
4. 预告文章将给出的解决方案
5. 一句话承诺读完后的收获
```

### 8. 反直觉钩子

```
用一个违反常识的观点开篇，引起读者好奇心。

话题：[TOPIC]
反直觉观点：[COUNTERINTUITIVE_POINT]
事实依据：[EVIDENCE]

引言要求：
- 第一句话就提出反直觉观点
- 用数据或案例佐证
- 解释为什么大多数人想错了
- 过渡到文章的深入分析
```

## 正文撰写 / Body Writing

### 9. 段落扩写

```
将以下要点扩写为完整的博客段落。

要点：[BULLET_POINT]
段落位置：[POSITION]（如文章开头/中间/结尾）
目标字数：[WORD_COUNT] 字
语气：[TONE]

要求：
- 用具体案例支撑论点
- 加入过渡句，承上启下
- 适当使用修辞手法
- 关键信息加粗
- 保持段落长度适中（3-5 句）
```

### 10. 技术概念解释

```
用通俗易懂的方式解释以下技术概念。

概念：[CONCEPT]
读者技术水平：[AUDIENCE_LEVEL]
文章上下文：[CONTEXT]

要求：
- 先用一句话给出直觉性理解
- 再用类比或比喻辅助理解
- 提供实际应用场景
- 如果适用，附上简单代码示例
- 总长 150-250 字
```

### 11. 过渡段撰写

```
为以下两个章节之间撰写自然的过渡段。

上一章节主题：[SECTION_A]
下一章节主题：[SECTION_B]
文章主题：[ARTICLE_TOPIC]

过渡段要求：
- 3-5 句话
- 回顾上节关键点
- 自然引入下节
- 保持读者阅读动力
- 不要使用生硬的"接下来我们来看..."
```

### 12. 案例研究撰写

```
撰写一个有说服力的案例研究段落。

案例主题：[CASE_TOPIC]
公司/项目：[COMPANY_OR_PROJECT]
背景：[BACKGROUND]
挑战：[CHALLENGE]
解决方案：[SOLUTION]
成果：[RESULTS]

撰写要求：
- 用 STAR 框架（Situation-Task-Action-Result）
- 包含具体数字和数据
- 突出关键转折点
- 总结可复制的经验
- 总长 200-300 字
```

## SEO 优化 / SEO Optimization

### 13. SEO 标题优化

```
为以下文章生成 SEO 友好的标题。

文章主题：[TOPIC]
目标关键词：[PRIMARY_KEYWORD]
次要关键词：[SECONDARY_KEYWORDS]

请生成 10 个标题选项：
- 包含数字的标题（如"7 种方法"）
- 包含年份的标题（如"2024 年指南"）
- 包含"如何"的标题
- 包含"最佳"的标题
- 问题式标题
- 对比式标题

每个标题附上预估 CTR（高/中/低）和推荐理由。
```

### 14. Meta Description 优化

```
为以下文章生成 5 个 Meta Description 变体。

页面标题：[PAGE_TITLE]
目标关键词：[KEYWORD]
文章摘要：[SUMMARY]

要求：
- 每个 150-160 字符
- 包含主关键词（自然插入）
- 包含行动号召（如"学习"、"了解"、"掌握"）
- 激发点击欲望
- 准确描述页面内容
```

### 15. 内容关键词优化

```
对以下博客内容进行 SEO 优化。

目标关键词：[KEYWORD]
当前内容：
```[CONTENT]```

优化项目：
1. 关键词密度检查（推荐 1-2%）
2. H1/H2/H3 标签中是否包含关键词
3. 首段是否包含关键词
4. 图片 Alt 文本建议
5. 内链建议位置
6. LSI（潜在语义索引）关键词推荐
7. URL slug 建议

输出优化后的内容和优化清单。
```

## 结尾与 CTA / Conclusions & CTA

### 16. 博客结尾撰写

```
为以下文章撰写一个有力的结尾。

文章主题：[TOPIC]
关键要点总结：[KEY_TAKEAWAYS]
目标行动：[DESIRED_ACTION]（如订阅/评论/分享/购买）

结尾结构：
1. 要点回顾（2-3 句话浓缩全文精华）
2. 金句或引用（给读者留下深刻印象）
3. 清晰的 CTA（告诉读者下一步该做什么）
4. 互动引导（提问引发评论）
```

### 17. 作者简介撰写

```
撰写一段专业且有亲和力的作者简介。

作者名：[AUTHOR_NAME]
专业领域：[EXPERTISE]
经历亮点：[HIGHLIGHTS]
当前角色：[CURRENT_ROLE]
社交链接：[SOCIAL_LINKS]

要求：
- 第三人称
- 50-80 字
- 包含权威性信息（经验年限、项目/成果）
- 包含个人特色（让读者记住你）
- 附带 CTA（如"关注获取更多[领域]内容"）
```

## 内容改写 / Content Rewriting

### 18. 长文章→短文章

```
将以下长文精简为 [WORD_COUNT] 字的精华版。

原文：
```[ORIGINAL_CONTENT]```

保留原则：
1. 保留核心观点
2. 删除重复论述
3. 合并相似段落
4. 保持逻辑完整性
5. 不丢失关键信息
```

### 19. 正式→口语化

```
将以下正式风格的博客改写为轻松口语风格。

原文：
```[CONTENT]```

改写要求：
- 用短句和简单词汇
- 加入口语表达（如"说实话"、"你猜怎么着"）
- 使用第一/第二人称
- 加入适当的幽默
- 保持专业性不变
```

### 20. 旧文章更新

```
更新以下旧博客文章，使其对 [YEAR] 年仍然相关。

原文：
```[OLD_CONTENT]```

更新要求：
1. 更新过时的数据和统计
2. 更新过时的工具/方法推荐
3. 添加新出现的趋势/工具
4. 移除已废弃的内容
5. 更新截图和示例
6. 标注[更新]标记，说明更新了什么
```

## 示例输出 / Example Output

**模糊 Prompt** → "帮我写一篇关于 Docker 的博客"

**精确 Prompt** → "为中级 DevOps 工程师写一篇 2000 字的 Docker 多阶段构建教程，包含 3 个实际项目示例，用教程风格，目标关键词是 'docker multi-stage build'"

| 维度 | 模糊 Prompt | 精确 Prompt |
|------|------------|------------|
| 内容深度 | 表面概述 | 深入实操 |
| 目标读者 | 不明确 | 精准定位 |
| SEO 效果 | 随机 | 有关键词策略 |
| 结构 | AI 自由发挥 | 按框架输出 |
| 可用性 | 需要大量修改 | 接近终稿 |

## 💡 使用技巧 / Tips

1. **明确受众**：读者是谁决定了内容的深度、语气和术语使用
2. **提供参考**：给 AI 看你想模仿的文章风格，效果更好
3. **分段生成**：大纲→引言→正文→结尾，分步比一次性生成质量高
4. **加入数据**：提供你想在文章中使用的数据，让 AI 帮你组织
5. **迭代优化**：第一次生成后，要求 AI 修改不满意的部分

## ⚠️ 常见错误 / Common Mistakes

- ❌ 不指定目标读者，导致内容深度不合适
- ❌ 不提供关键词，错失 SEO 机会
- ❌ 让 AI 一次生成整篇（分段生成质量更高）
- ❌ 不检查事实准确性（AI 可能编造数据和引用）
- ❌ 忽略文章的独特角度（避免千篇一律的内容）
