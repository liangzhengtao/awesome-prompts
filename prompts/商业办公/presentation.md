## 幻灯片内容 / Slide Content

### 1. 演示文稿大纲生成

```
为以下演示创建完整的幻灯片大纲。

演示主题：[TOPIC]
演示时长：[DURATION] 分钟
目标受众：[AUDIENCE]
演示目的：[PURPOSE]（如汇报/销售/培训/投资路演）
场合：[SETTING]（如董事会/行业大会/内部分享）

大纲格式（每页幻灯片）：
| 页码 | 标题 | 核心信息 | 视觉元素建议 | 讲师备注要点 |

幻灯片类型指导：
- 开场：1 张（钩子/震撼数据/问题）
- 议程：1 张
- 主体：[根据时长分配]
- 总结：1 张
- CTA：1 张
- Q&A：1 张

总体原则：每页一个核心信息，不超过 3 个要点。
```

### 2. 数据可视化幻灯片

```
将以下数据转化为有说服力的数据可视化幻灯片。

数据：
```[DATA]```

数据故事：[DATA_STORY]（你想通过数据传达的核心信息）
受众：[AUDIENCE]

请为每个数据点提供：
1. 推荐的图表类型（柱状/折线/饼图/散点/热力图等）
2. 幻灯片标题（结论导向，不是"XXX 数据"）
3. 关键洞察标注
4. 视觉设计建议（颜色/高亮/动画）
5. 讲师备注（如何解读数据）

原则：图表标题应直接陈述结论，而非描述图表本身。
```

### 3. 投资路演 PPT

```
为 [STARTUP] 创建投资路演演示文稿大纲。

公司名称：[COMPANY]
行业：[INDUSTRY]
融资轮次：[ROUND]
融资金额：[AMOUNT]
当前阶段：[STAGE]

标准路演结构（12 张幻灯片）：
1. 标题页（公司名+一句话定位）
2. 问题（市场痛点）
3. 解决方案（你的产品如何解决）
4. 市场规模（TAM/SAM/SOM）
5. 商业模式（怎么赚钱）
6. Traction（已有成绩/数据）
7. 竞争格局（竞争定位）
8. 团队（核心团队介绍）
9. 财务预测（3-5 年）
10. 融资需求（金额+用途）
11. 里程碑（接下来 18 个月）
12. 感谢页（联系方式）

每页需要：标题 + 核心数据/信息 + 视觉建议
```

### 4. 产品发布演示

```
为 [PRODUCT] 的发布会创建演示文稿大纲。

产品名称：[PRODUCT]
产品类型：[TYPE]
目标用户：[AUDIENCE]
核心卖点：[KEY_FEATURES]
定价：[PRICING]
竞品对比：[COMPETITORS]

演示结构（20-30 分钟）：
1. 开场（引人入胜的故事/问题，2 分钟）
2. 痛点展示（引起共鸣，3 分钟）
3. 产品亮相（"One More Thing" 时刻，2 分钟）
4. 核心功能演示（8-10 分钟）
5. 竞品对比（3 分钟）
6. 用户见证（3 分钟）
7. 定价和购买（3 分钟）
8. 总结和愿景（2 分钟）

每页幻灯片的具体内容和设计建议。
```

```

汇报人：[NAME]

汇报对象：[AUDIENCE]（如直属领导/高层管理/全员）
时间范围：[QUARTER]

1. 季度亮点总结（1 张，3 个关键成就）

```

## 演讲备注 / Speaker Notes

### 6. 逐页演讲备注

```
为以下演示文稿撰写详细的演讲备注。

演示文稿内容：
```[SLIDES_CONTENT]```

演示时长：[DURATION] 分钟
语气：[TONE]（如正式/轻松/激励/教育）
受众：[AUDIENCE]

每页备注需要包含：
- 开场白（如何引入这一页）
- 核心讲解（要传达的关键信息）
- 过渡语（如何连接到下一页）
- 时间分配建议
- 互动提示（提问/停顿/眼神交流）
```

### 7. 演讲者提词卡

```
将以下演讲内容转化为简洁的提词卡格式。

演讲内容：[SPEECH_CONTENT]
每张提词卡时长：约 [SECONDS] 秒

提词卡格式：
---
📍 卡片 [N] - [主题关键词]
⏱️ [开始时间] - [结束时间]
🔑 核心：[一句话核心信息]
📝 要点：
  - 要点 1
  - 要点 2
  - 要点 3
🔗 过渡：[连接下一段的话]
💡 提示：[语气/手势/停顿提示]
---

要求：每张卡片用词精炼，扫一眼就能想起来。
```

### 8. 演讲排练脚本

```
将以下演示内容转化为完整的排练脚本。

演示大纲：[OUTLINE]
幻灯片内容：[SLIDES]
总时长：[DURATION] 分钟

排练脚本格式：
| 时间 | 幻灯片 | 开场 | 关键句 | 结束/过渡 | 备注 |

要求：
- 标注停顿位置（⏸️）
- 标注互动点（🙋）
- 标注幽默/轻松时刻（笑点）
- 标注需要强调的词（**加粗**）
- 标注语速变化（⏩ 加速 / ⏸️ 减速）
```

## Q&A 准备 / Q&A Preparation

### 9. Q&A 预测和准备

```
基于以下演示内容，预测最可能被问到的问题并准备答案。

演示主题：[TOPIC]
演示内容摘要：[SUMMARY]
受众构成：[AUDIENCE_PROFILE]
可能的敏感话题：[SENSITIVE_TOPICS]

请预测：
1. 🔴 高概率问题（一定会被问到）- 5 个
2. 🟠 中概率问题（可能会被问到）- 5 个
3. 🟡 低概率但重要的问题 - 3 个

每个问题的回答格式：
- 简短回答（30 秒版本）
- 详细回答（2 分钟版本）
- 支撑数据/案例
- 反问/引导（将问题转化为优势）
```

### 10. 棘手问题应对

```
准备应对以下演示场景中的棘手问题。

场景：[SCENARIO]（如投资路演/季度汇报/产品发布）
潜在挑战性问题：
[DIFFICULT_QUESTIONS]

对每个问题准备：
1. 认可提问者（不防御）
2. 诚实回答（不回避）
3. 转向优势（桥接技巧）
4. 提供数据/证据
5. 收尾金句

额外准备：
- "我不知道"的优雅回应方式
- 将负面问题转化为正面展示的机会
```

## 故事叙述 / Storytelling

### 11. 商业故事构建

```
将以下商业信息转化为一个引人入胜的故事。

核心信息：[KEY_MESSAGE]
数据/事实：[DATA_POINTS]
目标：[GOAL]（说服/激励/教育/记录）

故事结构：
1. 场景设定（让受众置身其中）
2. 冲突/挑战（制造张力）
3. 转折点（关键决策/洞察）
4. 解决方案（你的方案/产品/策略）
5. 结果（数据+情感）
6. 启示（核心信息升华）

要求：
- 用第一人称或第三人称叙事
- 包含具体细节和场景描写
- 让数据成为故事的一部分
- 控制在 3-5 分钟口述时长
```

### 12. 数据故事化

```
将以下数据转化为有说服力的故事。

原始数据：
```[RAW_DATA]```

核心论点：[ARGUMENT]
受众：[AUDIENCE]

故事化技巧：
1. 选择一个数据点作为"主角"
2. 展示"之前vs之后"的对比
3. 用百分比/比率让数字更直观
4. 将大数字转化为可感知的类比
5. 加入人类故事（数据背后的人）

输出：
- 开头钩子（用数据制造惊讶）
- 故事主线
- 关键数据点的呈现方式
- 结论和行动号召
```

## 演示优化 / Presentation Polish

### 14. 演示文稿诊断

```
诊断以下演示文稿的问题并给出改进建议。

演示文稿内容/大纲：
```[PRESENTATION_CONTENT]```

诊断维度：
1. 结构（逻辑是否清晰，是否有明确的开头/中间/结尾）
2. 信息密度（每页信息量是否合适）
3. 受众匹配（内容深度是否适合受众）
4. 视觉层次（信息优先级是否清晰）
5. 故事性（是否有引人入胜的叙事线）
6. CTA（是否有明确的下一步行动）
7. 时间分配（各部分时间是否合理）

输出诊断报告 + 每个问题的改进建议。
```

### 15. 幻灯片文案优化

```
优化以下幻灯片的文案，使其更具冲击力。

当前文案：
```[CURRENT_TEXT]```

优化方向：
- 标题：用结论/行动导向替代描述性标题
- 要点：每个要点不超过 15 个字
- 数据：用对比/类比让数字更直观
- 语言：用主动语态、简洁有力

输出优化前后的对比表。
```

### 16. One-Pager 生成

```
将以下演示文稿浓缩为一页纸摘要。

演示文稿内容：
```[PRESENTATION]```

One-Pager 结构：
- 顶部：标题 + 一句话总结
- 左栏：关键要点（3 个）
- 右栏：核心数据/图表
- 底部：下一步行动 + 联系方式

要求：打印在 A4 纸上清晰可读，留有足够白边。
```

## 💡 使用技巧 / Tips

1. **明确场合**：董事会汇报和行业大会的风格完全不同
2. **控制时长**：告诉 AI 精确的演示时长，它会帮你合理分配
3. **提供受众背景**：受众的专业程度决定了内容的深度
4. **分步生成**：大纲→内容→备注→Q&A，分步质量更高
5. **排练脚本**：要求 AI 生成排练脚本，帮你把控时间和节奏

## ⚠️ 常见错误 / Common Mistakes

- ❌ 幻灯片文字过多（每页不超过 30 字核心文字）
- ❌ 没有明确的叙事线（只是信息罗列）
- ❌ 数据展示缺乏解读（受众不知道该看什么）
- ❌ 忽略 Q&A 准备（演示的 50% 在问答环节）
- ❌ 不考虑时间限制（内容塞太多讲不完）
