## 需求收集 / Requirements Gathering

### 1. 用户故事撰写

```
为以下功能需求撰写用户故事（User Stories）。

功能描述：[FEATURE_DESCRIPTION]
产品名称：[PRODUCT]
目标用户：[USER_PERSONA]
业务目标：[BUSINESS_GOAL]

每个用户故事请按以下格式：
### US-[NUMBER]: [标题]
**作为** [用户角色]
**我想要** [功能/行为]
**以便** [价值/目的]

**验收标准（AC）：**
- [ ] AC1: [具体可测试的条件]
- [ ] AC2: [具体可测试的条件]
- [ ] AC3: [异常场景处理]

**技术备注：** [技术约束/依赖]
**故事点：** [预估复杂度 S/M/L/XL]

请为该功能拆分为 5-10 个用户故事，并按优先级排序。
```

### 2. PRD（产品需求文档）

```
为以下功能编写产品需求文档（PRD）。

功能名称：[FEATURE_NAME]
产品名称：[PRODUCT]
优先级：[PRIORITY]（P0/P1/P2）
目标上线日期：[TARGET_DATE]

PRD 结构：
1. 概述（一段话说清楚做什么、为什么做）
2. 背景和目标
3. 用户场景（User Stories / Use Cases）
4. 功能需求（详细描述每个功能点）
5. 非功能需求（性能/安全/兼容性）
6. 交互设计要求（关键流程/状态说明）
7. 数据需求（需要哪些数据/如何获取）
8. 依赖和约束
9. 成功指标（如何衡量这个功能成功）
10. 排期建议和里程碑
11. 开放问题
```

### 3. 需求澄清问题清单

```
基于以下初步需求描述，生成一份需求澄清问题清单。

初步需求：[INITIAL_REQUIREMENT]
提出方：[STAKEHOLDER]
项目背景：[CONTEXT]

请从以下维度提出问题：
1. 业务目标（为什么要做？成功的标准是什么？）
2. 用户场景（谁在什么情况下使用？）
3. 功能范围（包含什么？不包含什么？）
4. 边界条件（异常情况如何处理？）
5. 性能要求（响应时间/并发/数据量）
6. 设计约束（兼容性/技术限制/时间限制）
7. 优先级（哪些是必须的？哪些可以后续做？）
8. 依赖（需要哪些团队/系统配合？）

每个问题标注优先级（必须澄清/应该澄清/最好澄清）。
```

### 4. 技术方案评审清单

```
为以下技术方案生成评审检查清单。

技术方案文档：[TECH_DOC_SUMMARY]
项目类型：[PROJECT_TYPE]
关键约束：[CONSTRAINTS]

评审清单：
1. ✅ 架构合理性
   - 方案是否满足功能和非功能需求
   - 是否考虑了扩展性
2. ✅ 技术选型
   - 技术栈是否合适
   - 是否有学习成本/迁移成本
3. ✅ 数据设计
   - 数据模型是否合理
   - 是否考虑了数据增长
4. ✅ 安全性
   - 是否有安全评审
   - 数据保护措施
5. ✅ 性能
   - 是否有性能预估
   - 瓶颈在哪里
6. ✅ 可运维性
   - 监控方案
   - 故障恢复
7. ✅ 排期合理性
   - 工作量评估是否准确
   - 是否有缓冲时间
```

## 风险评估 / Risk Assessment

### 5. 项目风险识别

```
识别以下项目的潜在风险。

项目名称：[PROJECT_NAME]
项目描述：[PROJECT_DESCRIPTION]
团队规模：[TEAM_SIZE]
时间框架：[TIMELINE]
预算：[BUDGET]
技术栈：[TECH_STACK]
关键依赖：[DEPENDENCIES]

风险评估矩阵：
| 风险编号 | 风险描述 | 类别 | 概率(1-5) | 影响(1-5) | 风险值 | 应对策略 | 负责人 |

风险类别：
- 技术风险（技术选型/架构/集成）
- 进度风险（依赖/范围蔓延/资源）
- 人员风险（离职/技能/协作）
- 外部风险（市场/政策/第三方）
- 质量风险（缺陷/性能/安全）

输出：
1. 风险清单（按风险值排序）
2. Top 5 高风险详细分析
3. 风险应对计划
4. 风险监控机制建议
```

### 6. 技术债务评估

```
评估以下项目的技术债务状况。

项目名称：[PROJECT_NAME]
项目年龄：[PROJECT_AGE]
技术栈：[TECH_STACK]
代码规模：[CODE_SIZE]
团队规模：[TEAM_SIZE]

请评估以下维度（1-10 分）：
1. 代码质量（可读性/一致性/规范）
2. 测试覆盖（单元测试/集成测试/E2E）
3. 架构健康（模块化/耦合度/可扩展性）
4. 依赖健康（依赖版本/安全漏洞/维护状态）
5. 文档完整度（API 文档/架构文档/运维文档）
6. CI/CD 健康度（自动化程度/构建时间/部署频率）
7. 监控和可观测性

输出：
- 各维度评分和分析
- 技术债务热力图（哪些最紧急）
- 偿还优先级建议
- 偿还计划（按季度）
```

### 7. 上线检查清单

```
为以下项目/功能生成上线检查清单。

项目/功能：[FEATURE_NAME]
上线环境：[ENVIRONMENT]
上线方式：[DEPLOY_METHOD]（如蓝绿/金丝雀/全量）
回滚方案：[ROLLBACK_PLAN]

检查清单类别：
1. ✅ 代码就绪
   - [ ] 代码已合并到发布分支
   - [ ] 所有测试通过
   - [ ] 代码审查完成
2. ✅ 测试验证
   - [ ] 功能测试通过
   - [ ] 性能测试通过
   - [ ] 安全扫描通过
3. ✅ 数据准备
   - [ ] 数据库迁移脚本就绪
   - [ ] 数据备份完成
4. ✅ 环境准备
   - [ ] 配置更新
   - [ ] 环境变量设置
5. ✅ 监控告警
   - [ ] 关键指标监控就绪
   - [ ] 告警规则配置
6. ✅ 应急准备
   - [ ] 回滚方案验证
   - [ ] 值班人员确认
7. ✅ 通知相关方
   - [ ] 团队通知
   - [ ] 用户公告（如需要）
```

```
[COMPLETED_ITEMS]

进行中：
[IN_PROGRESS_ITEMS]

下周计划：
[NEXT_WEEK_PLAN]

[BLOCKERS]
```

## 回顾总结 / Retrospectives

### 11. Sprint 回顾

```
组织一次 Sprint 回顾会议。

Sprint 信息：
- Sprint 编号：[SPRINT_NUMBER]
- 周期：[SPRINT_DURATION]
- 目标：[SPRINT_GOAL]
- 完成情况：[COMPLETION_RATE]
- 团队规模：[TEAM_SIZE]

回顾框架选择：
A. Start-Stop-Continue（开始-停止-继续）
B. 4Ls（Liked-Learned-Lacked-Longed For）
C. Mad-Sad-Glad（生气-难过-开心）
D. Sailboat（帆船：风=动力，锚=阻力，礁石=风险，岛=目标）

请按选择的框架：
1. 设计回顾会议议程（含时间分配）
2. 准备引导问题
3. 提供记录模板
4. 生成行动项模板
```

### 12. 项目复盘报告

```
为已完成的项目撰写复盘报告。

项目名称：[PROJECT_NAME]
项目周期：[START_DATE] - [END_DATE]
项目目标：[ORIGINAL_GOALS]
实际结果：[ACTUAL_RESULTS]
团队：[TEAM]

复盘报告结构：
1. 项目概况（一段话总结）
2. 目标达成情况
   | 目标 | 计划 | 实际 | 达成率 | 原因分析 |
3. 做得好的（Keep）
   - 具体事件 + 为什么好 + 如何复制
4. 需要改进的（Improve）
   - 具体事件 + 根因分析 + 改进方案
5. 学到的教训（Lessons Learned）
6. 时间线回顾（里程碑 + 偏差分析）
7. 预算回顾
8. 团队反馈总结
9. 对未来项目的建议
```

## 项目规划 / Project Planning

### 14. 项目 WBS（工作分解结构）

```
为以下项目创建工作分解结构（WBS）。

项目名称：[PROJECT_NAME]

WBS 层级要求：
- Level 1: 项目
- Level 2: 阶段/模块
- Level 3: 具体任务

| WBS 编号 | 任务名称 | 负责人 | 预估工时 | 前置依赖 | 交付物 |

```


## 💡 使用技巧 / Tips

1. **提供上下文**：项目类型、团队规模、方法论（敏捷/瀑布）等信息很重要
2. **指定模板**：如果你有公司模板，给 AI 看模板格式
3. **数据驱动**：提供实际数据（完成率、速度等），报告会更真实
4. **明确受众**：给管理层的报告和给团队的报告风格不同
5. **迭代完善**：先生成框架，再逐节深化

## ⚠️ 常见错误 / Common Mistakes

- ❌ 风险评估过于乐观（要保守估计）
- ❌ 状态报告只报喜不报忧（要诚实）
- ❌ 需求不拆分就开始排期（先拆到可执行级别）
- ❌ 回顾会变成批斗会（聚焦改进而非追责）
- ❌ WBS 遗漏非开发任务（测试/文档/部署等）
